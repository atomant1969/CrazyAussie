How To Use This Project

Parent: Index

Tool: Start Here HTML

Short Answer

If you downloaded this project from GitHub, open:

START_HERE.html

That file opens in a normal web browser and gives you clickable navigation to generated HTML pages.

Why Use HTML Pages

The project documents are browser-ready HTML files. That means you can open them locally without needing a Markdown viewer, VS Code preview, or GitHub rendering.

For local browser use, open START_HERE.html and follow the links to the pages in the html folder.

Best Ways To Use The Project

Option 1: Use The Browser Start Page

Best for non-technical use.

  1. Download or clone the repo.
  2. Open the folder.
  3. Double-click START_HERE.html.
  4. Use the links to open the project index, checklist, and docs as browser-friendly HTML pages.

Option 2: Use GitHub

Best if viewing online or downloading the files.

  1. Open the repo on GitHub.
  2. Download or clone the repo.
  3. Open START_HERE.html locally.
  4. Use README.md only as the GitHub overview.

Option 3: Use VS Code

Best if editing the files.

  1. Open the folder in VS Code.
  2. Edit the HTML files directly.
  3. Open START_HERE.html in a browser to check navigation.
  4. Keep README.md as the only Markdown file.

Checklist Progress

Static checkboxes may not save when clicked in a preview.

Use CHECKLIST_APP.html for real progress tracking. It saves:

  • checked tasks
  • in-progress tasks
  • notes
  • collapsed sections
  • scroll position

The reference checklist is static. The interactive checklist uses three states: not started, in progress, and completed.

Progress is saved in the browser on that computer. Use Export Progress inside the checklist app if you want a backup.

Recommended Daily Workflow

  1. Open START_HERE.html.
  2. Open CHECKLIST_APP.html.
  3. Work from the current open tasks.
  4. Add notes as you go.
  5. Export progress occasionally.
  6. Use Index.html when you need to navigate the full planning system.
